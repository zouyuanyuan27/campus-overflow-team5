# Developer 角色承诺书

> 对应课程手册 2.3.3《Developer 角色承诺书》，与纸质签字版内容一致。

我，**张嘉雨**（签名），自愿担任 **计科2412班第5组** 组内的 Developer。
在本学期 4 个 Sprint 中承担如下职责：

1. 完成承诺的 Story 与 Task，达到团队 DoD 标准；
2. 编写充分的单元测试：团队整体覆盖率 > 70%，核心聚合达到 90% 以上（对齐 Lab7 质量门禁）；
3. 主动参与代码评审，每周至少完成 2 次实质性 PR 评审；
4. 在 Daily Standup 报告进展、计划、障碍；
5. 对自己代码的线上质量负责到底，不"提交即遗忘"；
6. 主动协助其他成员，不形成"代码孤岛"。

我承诺每个 Sprint 至少贡献 **3 个 Story Point** 工作量。
若实际产能下降将主动告知 SM，共同调整 Backlog。

承诺人签字：**张嘉雨**　　日期：**2026.9.9**

## 补充约定（与《团队章程 v1.0》联动，非手册模板内容）

为让上述职责可执行、可检查，补充以下量化约定：

| 职责条目 | 团队内的执行口径 |
| --- | --- |
| 第 1 条 DoD | 见 `docs/team/charter-v1.0.md` §4，共 9 条，全部满足才算完成（章程正文将随 `docs/team-charter` 分支合入，届时回填生效链接） |
| 第 2 条测试 | 领域逻辑先写测试再实现；异常与边界路径必须有用例；覆盖率按职责第 2 条口径（>70%，核心聚合 90%+，SonarQube 门禁 Coverage > 70%） |
| 第 3 条评审 | 对齐 Lab7 口径：每个 Sprint ≥ 4 次跨成员深度评审，每次 PR 留下 ≥ 5 条可验证、可执行的意见（命名/空值/边界/测试缺口），不接受只写 LGTM |
| 第 4 条站会 | 每天 21:00 群内文字站会，三句话：昨天 / 今天 / 阻塞 |
| 第 5 条质量 | 本人合入 `main` 的提交若引发 CI 失败，负责在当天内修复或回滚 |
| 第 6 条协作 | 卡住超过 30 分钟主动求助；帮助他人时先复现问题再给方案 |
